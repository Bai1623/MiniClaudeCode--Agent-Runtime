# miniClaudeCode 项目交接文档

更新时间：2026-08-31

## 1. 项目一句话定位

miniClaudeCode 是一个基于 Python 实现的轻量级 AI Coding Agent Runtime。

它不是简单聊天机器人，也不是只包一层 Claude API，而是围绕真实代码智能体的核心链路做工程化实现：Agent Loop、Tool Runtime、权限控制、长任务 Harness、Git Workflow 工程闭环、长期记忆与上下文压缩。

推荐在简历中使用的项目名：

```text
MiniCode Agent：轻量级 AI 编程助手运行时
```

推荐项目描述：

```text
基于 Python 实现轻量级 AI Coding Agent Runtime，围绕 AI 编程助手的核心链路，设计并实现 Agent Loop、工具运行时、权限控制、长任务编排、Git 工程闭环和长期记忆上下文管理，用于探索 Coding Agent 在复杂工程任务中的安全执行、可观测性、可验证交付和上下文复用能力。
```

## 5. 第一层：Agent Loop

核心文件：

```text
miniclaudecode/agent_loop.py
```

作用：

```text
负责调用 Anthropic Messages API，解析模型返回的 text 和 tool_use，把工具执行结果重新放回上下文，形成多轮工具调用循环。
```

关键理解：

Anthropic Messages API 提供 Claude 的 LLM 能力。模型会根据当前上下文决定是直接回答，还是返回一个 `tool_use`。

模型只负责“决定要调用什么工具以及传什么参数”，不会真正执行本地命令或读写文件。真正执行的是本项目里的 `AgentLoop + ToolRuntime`。

面试讲法：

```text
AgentLoop 是项目的主循环，它负责把用户请求、历史消息和工具 schema 发给 Claude。Claude 返回 text 时直接输出，返回 tool_use 时，AgentLoop 会把调用请求交给本地 ToolRuntime 执行，再把 tool_result 回填给 Claude，继续下一轮推理，直到模型给出最终回答。
```

## 7. 最近重点推进：工具输出压缩增强

最近几次主要围绕 Tool Runtime 的压缩策略做了增强。

原始问题：

```text
grep、bash、cat、测试日志等工具输出可能非常长，直接塞回模型上下文会浪费 token，甚至撑爆上下文。
```

基础策略：

```text
保留 head
保留 tail
中间插入 truncated marker
记录 metadata
```

进一步优化后，现在支持：

```text
head + 关键片段 + tail
```

按工具类型的策略：

```text
bash：优先保留 STDERR、Traceback、Error、Failed 等错误上下文
grep：优先保留 file:line:match 形式的命中行
默认：保留 error、exception、traceback、failed、timeout 等关键行
```

相关配置：

```text
max_tool_result_chars = 12000
tool_result_head_chars = 8000
tool_result_tail_chars = 4000
tool_result_snippet_lines = 80
```

环境变量：

```text
MINICLAUDECODE_TOOL_RESULT_SNIPPET_LINES
```

压缩 metadata：

```text
compressed
original_output_chars
kept_snippet_lines
snippet_tool
snippet_truncated
compression_strategy
```

`compression_strategy` 当前用于区分：

```text
snippet_only
head_tail
head_snippet_tail
```

这一步的工程价值：

```text
压缩不再只是粗暴截断，而是尽量在 token 预算内保留最有诊断价值的信息，并把压缩方式写进 trace，方便复盘和后续优化。
```


Trace 输入预览会递归脱敏 token、password、authorization 等敏感字段。
`write_file.content` 和 `edit_file.old_string/new_string` 只记录字符数和 SHA-256，不保存原文。

新增的 `miniclaudecode/runtime/trace_summary.py` 提供不可变 `TraceSummary`，可统计：

```text
工具调用数
错误类型分布
重试数

nearest-rank P50/P95 耗时
最慢的三次工具调用
```

意义：

```text
后续可以复盘 Agent 调用了哪些工具、哪个工具失败、失败类型是什么、耗时多少、输出是否压缩、压缩策略是什么。
```

## 9. 错误分类 error_type

相关文件：

```text
miniclaudecode/tools/base.py
miniclaudecode/runtime/tool_runtime.py
miniclaudecode/runtime/schema_validator.py
```

常见错误类型：

```text
unknown_tool
validation_error
permission_denied
preview_rejected
timeout_error
execution_error
workspace_violation
```

为什么不只写失败：

```text
is_error 只能说明失败了，error_type 才能说明为什么失败。
```

工程价值：

```text
不同失败类型可以走不同处理策略。参数错误可以让模型修正输入，超时可以对只读工具重试，权限拒绝要停止危险操作，workspace_violation 表示越界访问。
```

简历表达：

```text
设计结构化 ToolResult，引入 error_type 和 metadata，将工具调用失败从简单布尔值升级为可分类、可追踪、可统计的错误模型，提升 Agent 工具执行链路的可诊断性和可恢复性。
```
